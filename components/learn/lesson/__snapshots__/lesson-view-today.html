Find duplicates in one pass with a set

The slow way to find a duplicate is to compare every item with every other item. For a million items, that is about 500 billion comparisons.

The fast way: keep a set of the items you have already seen. For each new item, check if it is in the set. That check takes the same short time however big the set gets, which is called constant time. So you go through the list only once.

    To find duplicates, I keep a set of the items I have already seen. For each item I check the set first, which takes constant time on average. So the search takes linear time instead of quadratic time, and it uses extra memory for the set.

    In 2011, researchers showed that one web request could keep a server busy for minutes. The request had thousands of form fields, all chosen to land in the same hash bucket. Since then, Python and Ruby pick new random hashes for strings every time they start, and PHP limits how many fields a request can have.

Lesson 3 of 9

Find duplicates in one pass with a set

Finding out whether a list has a duplicate looks simple, and the simple way is slow.

The slow way. Compare every item with every other item. With 1,000 items that is about 500,000 comparisons. With a million items it is about 500 billion, which is minutes of work for something that should take a moment. The work grows with the square of the size: a list ten times longer takes a hundred times longer.

The idea. Go through the list once and keep a set of the items you have already seen. For each new item, ask the set one question: have I seen this before? If yes, you found a duplicate and can stop. If no, add the item and move on.

Why it is fast. A set does not search through its items. It works out a number from the item, called a hash, and looks in the one place that number points to. So the check takes about the same short time for 10 items and for 10 million. This is called constant time. One pass with a constant-time check is linear time: a list ten times longer takes ten times longer.

What it costs. Memory. The set holds every different item it has seen, so in the worst case it grows as large as the list.

When it does not fit. The items must be something a set can hold, such as numbers or strings. And a set forgets order: if you need to know where the first copy was, keep a hash map from the item to its position instead.
